기존 로그인 및 회원가입, Q26-LPA 6유형 분류, 사전진단 채점, 실전 미션 25개와 Luna API 기능은 **변경하지 않습니다.**

**추가되는 기능**

- 질문 / 학습 후기 / 정보 공유 분류, 제목·본문 검색

- 게시글 신고 접수 정보 저장 (운영자 신고 검토 페이지는 아직 없음)
- 기존 Figma 홈/사전진단 화면에 커뮤니티 메뉴 연결 (HTML 원본 파일은 그대로 유지)

**변경·추가 파일 5개** (`app.py`가 있는 폴더에 모두 넣기)
1. `app.py` — `community` 라우트, 로그인 접근 제어 및 상단 메뉴 1개 추가. **기존 파일 교체**.

5. `verify_community.py` — 임시 SQLite로 실행하는 회귀 테스트. **신규 파일**, 배포 필수는 아님.

## 3. Streamlit 작동 확인

- 홈/사전진단 소개 화면 상단 메뉴에 `커뮤니티`가 노출되는지 확인
- 로그아웃 상태에서 클릭하면 로그인 화면으로 이동하는지 확인
- 새 회원은 12문항 설문 완료 후 커뮤니티에 들어갈 수 있는지 확인
- 테스트 계정 A로 질문 글 작성 / 목록 검색 / 수정 확인
- 테스트 계정 B로 A의 글을 읽고 댓글 작성
- B 계정에서 A의 수정·삭제 버튼이 나타나지 않는지 확인
- A 계정에서 글을 삭제하면 댓글도 함께 삭제되는지 확인
- 신고 접수 버튼이 작동하는지 확인 (운영자 검토 UI는 아직 없음)
- 기존 로그인, Q26-LPA 결과, 25개 미션이 그대로 동작하는지 확인

## 4. 데이터베이스 및 보안

- 기존 `store.connect()`를 사용하므로 `DATABASE_URL`이 설정된 PostgreSQL에서는 같은 DB에 새 테이블 3개를 최초 이용 시 생성합니다: `community_posts`, `community_comments`, `community_reports`.
- 게시글·댓글의 실제 수정/삭제 SQL은 `WHERE ... AND user_id=?`로 소유자를 확인합니다.
- 출력은 `st.text`/기본 Streamlit 출력만 사용하며 사용자 입력 문자열에 HTML 렌더링 권한을 부여하지 않습니다.
- 글·댓글 길이, 분류, 신고 사유 입력을 서버에서 검증합니다.
- 사용자의 개인정보, 비밀키, 비밀번호를 게시하지 않도록 안내문을 노출합니다.
- **운영자 신고 검토, 게시글 숨김/차단, 신고 알림, 스팸 방지, 서비스 이용규칙/개인정보 처리방침**은 아직 구현하지 않았습니다. 외부 공개 서비스 확대 전에 별도 구축이 필요합니다.
- Streamlit Community Cloud에서 로컬 SQLite만 쓰면 재배포/재시작 시 자료가 사라질 수 있습니다. 지속 보존에는 운영 PostgreSQL의 `DATABASE_URL`이 필요합니다.
- 이 패치에는 실제 사용자 DB 파일, API 키 또는 `.env` 파일이 포함되지 않습니다.

## 5. 검증 내역

임시 SQLite에서 다음 항목을 확인했습니다: 테이블 중복 생성 안전성, 게시글 CRUD, 권한 검사, 댓글 CRUD, 신고 중복 처리, 검색/카테고리, 페이지네이션, 게시글 삭제 시 댓글/신고 CASCADE, 기존 테이블·사용자 유지.

기존 코드 사본에 이 패치를 적용하고 아래 테스트가 통과했습니다.
- Q26-LPA 테스트 6개
- 사전진단 채점 회귀 테스트 3개
- 미션 25개 스키마 검사
- 커뮤니티 저장소 테스트
- 홈/사전진단 HTML 링크 및 `app.py` 라우트 정적 확인

실제 Streamlit 브라우저 UI 클릭 및 운영 PostgreSQL 연결은 **아직 직접 검증하지 않았습니다.**

## 6. 로컬 테스트(선택)

Python이 설치된 환경에서 `app.py`가 있는 폴더로 이동하여:

```bash
python -m pip install -r requirements.txt
python verify_community.py
python -m streamlit run app.py
```

`verify_community.py`는 임시 DB만 사용해 실제 사용자 기록에 영향을 주지 않습니다.
