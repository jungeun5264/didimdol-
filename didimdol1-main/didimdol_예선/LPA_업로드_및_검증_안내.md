# 디딤돌 — 기존 Q26 설문 기반 LPA 6유형 분류 적용

## 0. 어떤 버전을 바꾸나요?

- 이전에 만든 **3단계(12문항·6유형 설문)** 기능이 반영된 디딤돌 앱을 기반으로 합니다.
- 이번 변경은 앞서 만든 '5점 척도 · 유형당 2문항 합산' 임시 분류를 **4점 척도 · Q26 3문항씩 4영역 평균 · 기존 학습된 LPA 모형으로 확률 분류**로 교체합니다.
- 기존 `app.py`, `auth.py`, `test.py`, `luna_service.py`, `training.py`, `scoring.py` 등은 이번 ZIP에서 교체하지 않습니다.
- 동일 저장소의 `app.py`에서 `onboarding` 페이지 이동과 `store.initialize()` 호출이 이미 구현되어 있어야 합니다.

## 1. 어디에 업로드하나요?

GitHub 저장소 `jungeun5264/didimdol-`에서 **현재 `app.py`, `store.py`, `mypage.py`가 있는 같은 폴더**를 열어 아래 파일을 올립니다. **ZIP 파일 자체를 업로드하는 것이 아닙니다.**

### 수정되는 기존 파일 (4개)

- `user_types.py` — 12개 Q26 문항/4점 척도/4개 평균/LPA 6개 사후확률/대표 유형
- `onboarding.py` — 회원가입 후 Q26 설문 화면, 3문항씩 4단계
- `store.py` — 기존 DB를 보존하는 `lpa_type_profiles` 테이블과 저장/조회
- `mypage.py` — 마이페이지 '나의 AI 활용 유형' 탭을 LPA 결과로 교체

### 새로 추가하는 파일 (5개)

- `LPA_inference_only.json` — 팀이 제공한 추론용 LPA 모형 파라미터 (원자료 포함하지 않음)
- `legacy_user_types.py` — 기존 5점 설문 결과/구형 저장 함수의 해석을 위해 보관
- `classification_smoke_tests.json` — 팀이 제공한 가상 입력에 대한 기대 결과
- `verify_lpa.py` — 계산/DB 보존 테스트
- `verify_onboarding.py` — 이전 테스트 실행 이름의 호환성 유지

`LPA_업로드_및_검증_안내.md`는 **코드 실행에는 필요하지 않은 설명서**입니다.

## 2. 적용 방법

1. **현재 GitHub 저장소의 브랜치를 백업**하거나 별도 브랜치에서 시작합니다.
2. ZIP을 풀고 위 파일 9개를 `app.py`가 있는 폴더에 업로드합니다.
3. GitHub에서 업로드 결과를 확인합니다. 특히 `LPA_inference_only.json`은 Python 파일과 같은 폴더에 있어야 합니다.
4. Streamlit 앱을 재시작/재배포하고 **새 테스트 계정**으로 회원가입합니다.
5. 회원가입 → 4영역 × 3문항(총 12문항) → 마이페이지 유형 결과가 표시되는지 확인합니다.
6. 기존 사용자는 과거 결과를 유지하고, 마이페이지의 `새 12문항 설문 시작하기`에서 새 방식으로 다시 분류할 수 있습니다.

기존 데이터베이스 테이블은 삭제하거나 덮어쓰지 않습니다. 신규 `lpa_type_profiles` 테이블만 추가됩니다. **프로덕션 DB 변경 전에는 백업하세요.**

## 3. 테스트 명령

`app.py`가 있는 폴더에서:

```bash
python verify_lpa.py
```

또는 기존 실행 습관을 유지하려면:

```bash
python verify_onboarding.py
```

테스트는 임시 SQLite 파일을 사용하며 실제 사용자 데이터베이스를 건드리지 않습니다.

가상 입력 확인 사례:

| 12문항 응답 | 예상 유형 | 특이사항 |
|---|---|---|
| 전부 1점 | C1 · AI 첫걸음형 | |
| 앞 9문항 1점, 마지막 3문항 3점 | C2 · 안전 인식 우세 입문형 | |
| 전부 2점 | C3 · 기초 활용형 | |
| 앞 9문항 2점, 마지막 3문항 3점 | C4 · 안전 인식 우세 확장형 | |
| 전부 3점 | C5 · 실용 활용형 | **C6와 소속확률이 매우 근접** |
| 전부 4점 | C6 · 숙련 활용형 | |

## 4. 반드시 알아둘 점

1. **모형 자체는 다시 학습하지 않았습니다.** 팀이 제공한 `LPA_inference_only.json`의 `pi`, `means`, 공통 `covariance`를 그대로 사용합니다.
2. **입력값을 표준화/100점 환산/역코딩하지 않습니다.** 12문항 1~4점 응답과 3문항 평균을 모형에 직접 넣습니다.
3. `is_close` 안내에 쓰는 **상위 2유형 확률차 10%p 미만**은 서비스 UX를 위한 임시 값입니다. 통계적으로 검증된 판정 임계값은 아닙니다.
4. **문항 의미와 응답 점수 방향은 팀 전달안과 동일하게 적용**했습니다. 다만 **1~4점 응답 선택지의 정확한 원조사 문구(앵커)**는 제공 자료에 없어 편의상 작성했으니, 실제 원본 조사표와 대조하고 필요하면 UI 문구를 수정해야 합니다.
5. 유형의 사후확률은 분류 모형 내 **소속확률**이며 사용자의 객관적 AI 능력이나 테스트 정답 확률이 아닙니다.
6. 이전 5점 설문 기록은 보존하되, 4점 LPA 모델 결과로 자동 변환하지 않습니다.
7. 유형별 교육 추천 순서 자동화는 아직 포함하지 않았습니다. **유형별 교육 선호도 데이터/정책**이 제공되면 다음 단계에서 연결할 수 있습니다.
8. 이 패치는 이전 **3단계 코드**를 기준으로 만든 것이며, GitHub의 최신 브랜치에 추가 변경이 있다면 적용 전 충돌 여부를 확인하세요.
9. `LPA_inference_only.json`은 사용자 응답 원본을 포함하지 않지만, **API 키와 DB 주소는 GitHub에 올리지 마세요.** 저장소 최상위에 `.gitignore`를 두고 `.sqlite3`, `.env`, `secrets.toml` 등을 제외하세요. 기존 Git 추적 파일은 `.gitignore`만으로 삭제되지 않습니다.

## 5. 검증 범위

- 6개 제공 가상 입력의 예상 소속확률과 실제 계산 비교: 오차 0.0001 이내 통과.
- 입력 누락·0/5점·문자·실수·불리언 거부.
- 신규 회원 설문 완료 처리와 기존 5점 설문/사전진단/훈련 기록 보존.
- Python 구문 및 데이터베이스 단위 테스트 통과.
- **실제 웹 브라우저 클릭, PostgreSQL 운영DB, 외부 API, 전체 통계모형의 원자료 적합도는 별도 확인 필요.**
